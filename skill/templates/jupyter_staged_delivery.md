# T4 · 案例模板：Jupyter 交付分阶段模板（PC 预演 → 上传核对 → 板上分格判活）

- **类型**：案例模板（流程/单元格序列骨架）
- **适用场景**：把 Python 交付物（主程序 + 插件/组件 + 网页资源）部署到 PYNQ 板 Jupyter 环境并做长跑验证；团队交付包首次引入。
- **使用方法**：A→B→C→D→E 五阶段顺序走；每个单元格（格）第一行都做 `sys.path.insert`；正式流程 = 干净 kernel 一次跑完，中途不插带收尾的独立格（纪律见 §6）。
- **失效条件**：① Windows 预演不加 `PYTHONIOENCODING=utf-8` 会在含 Unicode 输出时"假失败"（检查其实全过，exit=1）；② 主脚本若存在配置地板（如固定窗口长度使某指标到不了理想值），判读时要区分"地板"与"回归"（看三个次要证据再判）；③ 板上只有 numpy + 标准库，交付前按"最不利口径"（板端旧版本库 + 最慢负载）离线预演。
- **已验证效果**：该流程在某次 11 组件 + 网页三件套的交付中一次到位；首轮全量板测五阶段跑完，组件层逐个量化（单次耗时 max 均在预算内），此后三次板测均一轮跑完。
- **来源**：某次插件轨道首次上板：曾因"带收尾的独立验收格污染后续正式流程"三档全崩（漏投 91%、显示拦帧数千、输出全 nan），复盘后固化为五阶段 + 全程纪律。

---

## A 阶段：PC 预演（不占板子）

```powershell
$env:PYTHONIOENCODING='utf-8'; python tests\test_offline.py    # 离线回归，判据：末尾"全部通过"
python tools\web_demo.py --seconds 120                          # 网页/前端预演，开浏览器核对
```

**核对点**：波形/主视图连续刷新、关键指标数值合理、各卡片有数、事件流无误报抖动、按钮/落盘功能可用。**为什么要先做**：网页端的一切（布局/交互/事件）在这里先验收，上板后只需关心"数据对不对"。

## B 阶段：上传清单 + 上传后必跑核对格

两列表逐条走："传什么 / 板上放哪（覆盖或新增）"。整包传到 `<PKG>`；**别传** `*.bak*`、`__pycache__`、源码树整包。
**关键限制**：Jupyter `Upload` 只落**当前 notebook 所在目录**，进不了子目录——带目录结构用 Terminal（`scp`/`wget`/`rz`）或"搬运格"（见 T3 §4）。
传完立刻跑 T3 的两个核对格（落点格 + 版本格）。

## C 阶段：板上五步分格判活（每步独立判据，失败停在最靠前的 FAIL）

| 步 | 内容 | 判据 |
|---|------|------|
| 1 | 基线回归（不带任何组件） | 自检清单全过 + 速率实测 + 主循环统计正常 + 产物生成 |
| 2 | 最小组件集（2 个） | 与步骤 1 输出**逐段一致**；组件层单次耗时 `avg < 3ms / max < 15ms`；无超预算告警 |
| 3 | 加记录器 | 落盘条数 ≈ 实测速率 × 时长（±5%）；序号列严格递增无重复 |
| 4 | 加网络监视 | 浏览器 `<板IP>:<端口>` 页面连续；软件口径速率 ≈ 标定速率 |
| 5 | 全组件长跑 10 min | 速率指标稳定、丢弃数不持续增长、收尾逐组件 max 在预算内 |

## D 阶段：任一步不达标 → 逐组件二分定位

原则：**组件层问题不阻塞基线**，永远可退回步骤 1 的已验证状态。每次只多开一个组件跑，看收尾"组件层"逐组件 `avg/max` 与超预算日志（连续异常会自动停用并打印原因），直到爆表或速率掉的那个名字出现。二分期间**不要**中途重启 overlay / 新建硬件对象（会引入"使能回零"类干扰，见 K1 篇）。

## E 阶段：事后分析格（产物盘点 + 组件单体试验台）

```python
# [1/2] 产物盘点：四类模式逐项打印字节数
import glob, os
for pat in ['wave_*.csv', '<快照>_*.json', 'records/session_*/*.json', 'records/session_*/part*.csv']:
    for f in sorted(glob.glob(pat)):
        print(f, os.path.getsize(f), 'B')

# [2/2] 组件单体试验台：不碰硬件、不碰显示，最干净的组件层调试
from <包名> import PluginHost, Snapshot
host = PluginHost.from_spec('<组件a>,<组件b>', fs=<实测fs>, out_dir='.', verbose=True)
snap = Snapshot(wave=<一段真实或合成数据>, fs=<实测fs>, hr=<可选>, ...)   # 字段以板上实际签名为准
host.dispatch(snap); print(host.summary())
```

## §6 全程纪律（一次建链跑到底）

1. **每格第一行**都做 `sys.path.insert(0, '<PKG>')`；
2. 正式流程 = **干净 kernel 一次跑完**格 1→2→3，中途不插带收尾的独立格；
3. 验收取证放流程**前**或另开 kernel；
4. 收尾 `close()/stop()` **整场只做一次**，之后不要 close 后重开显示（实测：独立格结尾 close + stop + 自建硬件对象 → 重下 overlay → PL 重配 → 控制寄存器全局回零 → 后续复用旧对象的格全部崩坏：漏投 91%、显示拦帧 3152、输出全 nan）。

## 预期输出与判读

- A 阶段：离线回归"全部通过" + 浏览器预演核对点逐项勾选；
- C 阶段：五步各出一行判据结论，失败停在最靠前 FAIL；
- E 阶段：产物清单（路径 + 字节数）+ 组件单帧耗时表。

## 来源

某次"多组件 + 网页监视"交付首次上板（11 组件 + 静态三件套）：A 阶段提前暴露前端问题省下板时；C 阶段五步判活量化到单组件毫秒（质量 21.0 / 报警 5.9 / 记录 12.1 / 网页 13.6 ms）；D 阶段判据源自"9 组件全开"部署验证。踩过的两个大坑（Upload 落点、独立验收格收尾污染）已分别沉淀进 T3 与本模板 §6。
