# T3 · 案例模板：部署版本核对表（双树同步 + 哈希留证）

- **类型**：案例模板（脚本模板 / 登记表模板）
- **适用场景**：任何"开发形态 ≠ 部署形态"的项目（板载 Python 包、构建产物、分发目录）；每次上板前的版本核对；交付验收留证；外部交付包合并后的无漂移确认。
- **使用方法**：先立双树纪律（§1），再维护四列核对表（§2），同步与审计交给脚本（`../scripts/version_audit.py`，只读审计；同步写入脚本可按 §3 判据自写），上板前后各跑一次核对格（§4）。
- **失效条件**：核对表第三列（两侧一致）**推不出**第四列（板上现在真是这一版）——Jupyter 上传落点错、子目录名拼错、`__pycache__` 旧字节码都会让板上仍跑旧代码；哈希一致也推不出"语义门"（改了会触发下游再生成的文件，改了就必须重生成，哪怕内容还原）。
- **已验证效果**：某次交付 28 文件同步全 `[OK]`、关键文件对哈希全 MATCH；另一日靠第四列 MD5 发现"板上关键模块仍是旧版（哈希对不上）"，避免了整轮无效排查。
- **来源**：某次"包内副本不一致"类事故与一次子目录名拼错（内容全对仍 `ModuleNotFoundError`）的复盘；两条都由核对表/核对格当场捕获。

---

## §1 双树纪律（源头只写一处，部署包由脚本生成）

```
<src>/                      ← 可维护源头：人读、可改、可测试（唯一编辑点）
<deploy_pkg>/               ← 部署包：板上只认这份；由同步脚本从 src 生成，绝不手改
tools/sync_pkg.py           ← 唯一同步出口：copy2 + 双侧重算哈希 + 退出码
```

- 改源头后只跑脚本；**绝不手工挑文件拷贝**——手工同步是"包内副本不一致"事故的根源。
- 双副本差异一律由脚本解释；合并 ≠ 验证，合并后仍需上板/回归另跑。
- 受管清单（哪些文件进入部署包）抽成脚本内的单一常量，同步与审计**共用**，防止两处口径分叉。排除项白名单：`__pycache__`、`*.bak*`、临时文件。

## §2 四列核对表（每行一个受管文件）

```markdown
| 文件（相对 src） | 部署侧路径 | sha256（前 16 位） | 板上实际（MD5/字节） |
|-----------------|-----------|-------------------|---------------------|
| core/sim_src.py  | pkg/core/sim_src.py | <sha256 前 16 位> | <上板 md5sum 实测> |
| core/plugins/x.py| pkg/core/plugins/x.py | <sha256 前 16 位> | 待上板核对 |
| tools/board_main.py | pkg/board_main.py | <sha256 前 16 位> | 待上板核对 |
```

四列分别回答四个问题：**源头是哪个文件 / 部署到哪 / 两侧是否一致 / 板上现在真的是这一版吗**。第四列只能上板取（`md5sum` 或核对格），不能用本地值填——这正是"本地全绿、板上跑旧代码"的唯一防线。

## §3 同步脚本判据（自写 `sync_pkg.py` 时照抄）

- 首行：`[sync] src → deploy_pkg，共 {N} 个文件`（`--dry-run` 追加标注）；
- 每文件一行：`  [OK ] {rel}  {sha256[:16]}`；不一致 `[BAD]` 并累计；
- 退出码：有不一致 `return 1`；`shutil.copy2` 之后**重新计算两侧哈希**（不能只信 copy 没报错）；
- 收尾打印两条口径提醒：① 两侧哈希一致 ② 语义门文件（改了必须重跑生成器）未越过。

## §4 上板前/上板后核对格（Jupyter 两格，缺一不可）

**上传后落点格**（防"Upload 只落 notebook 目录"与目录名拼错）：

```python
# [1/3] 全盘搜索刚上传的文件（Upload 的落点是 notebook 所在目录，进不了子目录）
import glob, os, hashlib, shutil
hits = glob.glob('/home/<user>/**/<文件名>', recursive=True)
print('找到:', hits)
# [2/3] 校验字节数/MD5 后搬运到正本目录
assert len(hits) >= 1
for h in hits:
    if os.path.abspath(h) != os.path.join('<PKG>', '<相对路径>'):
        shutil.copy(h, os.path.join('<PKG>', '<相对路径>'))
# [3/3] 回读校验
p = os.path.join('<PKG>', '<相对路径>')
md5 = hashlib.md5(open(p,'rb').read()).hexdigest().upper()
print('[核对]', p, os.path.getsize(p), 'B', md5)   # 与核对表第四列逐字符比对（含目录名！）
```

**上板后版本格**（防缓存与旧路径）：

```python
import sys; sys.path.insert(0, '<PKG>')
import <包名>, inspect
print('<包名> 来自:', <包名>.__file__)                    # ① 路径对不对（指向 .pyc/旧目录 → 清 __pycache__ 或重启 kernel）
src = inspect.getsource(<包名>.<新功能所在模块>)
print('含新特征串:', '<新功能的特征字符串>' in src)        # ② 特征串（新功能必含，必须 True）
import importlib; importlib.reload(<包名>)
from <包名>.plugins import available, import_errors       # ③ 组件清单
print('可用组件:', available, '导入失败:', import_errors)  # 判据：清单齐全、失败为空
```

**逐字符比对目录名**：`<目录a>` 传成 `<目录b>`（只差一个字母）这类错误，内容/大小全对也照样 `ModuleNotFoundError`——只比文件内容哈希查不出来，核对格必须连目录名一起比对；修完（Rename/`mv`）重启 kernel 清导入缓存。

## 预期输出

- 脚本行：`[sync] ... 共 N 个文件` + N 行 `[OK]` + 退出码 0；
- 核对表：四列填满，第四列全部"上板实测"值；
- 核对格：路径正确 / 特征串 True / 组件清单齐全三项全绿。

## 来源

某次多组件交付上板：同步脚本 28 文件全 `[OK]`；同周发生的两起事故——"上传两次板上行为没变"（Upload 落点错误）与"内容全对仍 import 不到"（子目录名拼错、只差一个字母，实测案例）——分别由落点格与逐字符比对捕获。第四列防线另有实战：某日靠 MD5 发现板上关键模块哈希与本地终版不符（仍是旧版），一次重传解决。
