# 仿真验证契约

- **类型**：蒸馏件（testbench 契约 + 判定纪律）
- **适用场景**：RTL/模块级功能验证；回归测试；"仿真显示能跑但不确定对不对"；第三方仿真器（ModelSim/Questa/VCS/Xcelium/Riviera）日志判读。
- **使用方法**：按 §1 在跑仿真**前**把 9 项输入定清楚；§2 预检；§3 判定五门；§4 失败分级与诊断；§5 最小复现与版本 bisect。
- **失效条件**：① 本文件不绑定具体仿真器，XSim 专有参数（覆盖率闭合、SAIF/VCD 采集）只在"官方调用提示"里指路；② 后综合/后实现模式要求对应阶段已完成，否则判"环境失败"而非"设计失败"；③ 覆盖率数字只有在测试计划先定的前提下才可解释，无计划时覆盖率只作参考。
- **已验证效果**：规则源自 AMD 官方技能 `vivado-simulate-rtl`（23 份 references 覆盖 7 种仿真器、UVM/种子回归/断言/覆盖率闭合、跨仿真器仲裁、最小复现、版本 bisect、无 GUI 波形取证），该技能在官方发布中带回归与验证脚本（`sim_env_doctor.py`、`validate_skill.py`）。
- **来源**：AMD 官方技能 `vivado-simulate-rtl`（依据各仿真器官方文档与 Vivado 用户指南）。

> **官方调用提示**：已安装 `vivado-simulate-rtl` 时优先调用（可直接驱动 XSim/Questa/ModelSim 等并产出覆盖率与波形）；本文件是不安装时的纪律与判定口径。

---

## §1 九项输入契约（跑之前定清楚，缺一项就是"没有判据"）

1. **工程**：`.xpr`，或非工程模式下的显式源文件清单。
2. **仿真集与顶层**：simset 名、top 模块（用 Tcl 查询，不假设）。
3. **后端**：默认 XSim；**不得静默换后端**（换后端要显式声明并做跨仿真器仲裁）。
4. **模式**：行为级 / 后综合功能级 / 后实现功能级 / 后实现时序级。
5. **测试契约与终态 PASS 条件**：什么情况算通过（唯一终态标记，如 `TEST_PASS`）。
6. **有限运行时间或 TB 自终止**：**禁止无界 `run all`**，除非 TB 有经验证的 watchdog 与终态 `$finish`。
7. **高级验证参数**（用到才需要）：UVM test 名、种子列表、plusargs、期望断言、覆盖率目标。
8. **活动采集参数**（用到才需要）：warm-up 窗口、测量窗口、层级/对象集。
9. **产物清单**：transcript、波形、覆盖率、活动文件、生成的 TB、脚本。

只问"无法从工程中发现"的项；第三方仿真器的安装/许可/编译库路径必须由用户给出，**不许猜站点路径**。

## §2 预检七项

1. 会话/工程可打开；2. part、工程模式、仿真器、simset、top、源文件、编译顺序、include、宏、语言组合全部确认；3. 所选模式所需阶段已完成；4. 运行时间有界（watchdog/`$finish`）；5. 第三方后端先做其专属预检；6. 上次启动失败/库版本不符/陌生主机 → 先跑环境体检脚本；7. **预检期间不改设计 RTL**（可以改验证专用文件，前提是用户要求）。

## §3 判定五门（全过才算 PASS）

1. 编译 **与** elaborate 均成功；
2. 仿真器正常返回；
3. **存在显式终态 PASS 标记**（或测试框架等价结果）；
4. 所有必需测试完成，无意外 error / fatal assertion / timeout；
5. 附加门（用到才判）：
   - UVM：summary 零 unexpected error/fatal，选中 test 完成；
   - 断言：结果与测试计划一致，无 ignore 或降级；
   - 随机回归：失败必须在**同种子**下复现才叫"可复现"；
   - 时序模式：SDF 注解成功——**SDF 被跳过 = 零延迟仿真，不是时序 PASS**。

**核心纪律：编译干净 ≠ 功能正确；仿真器正常退出 ≠ 功能正确。** 没有显式 PASS 标记的"跑完了"，一律按"未验证"处理。

## §4 失败分级（先分级，再动手）

非 PASS 归入五类：**design / testbench / environment / timeout / tool_defect**（合法输入上可复现的工具故障）。

- 读**完整 transcript**，定位**第一个因果错误**及其仿真时刻；后续级联错误是次要信息。
- 诊断取证：时钟/复位、事务限定符、输入、期望值、实际输出、测试状态；优先接口与 TB 信号，内部信号只在必要时加。
- **不要因为仿真失败就改 RTL**：先定级。请求是"只诊断"时，给出证据链后即停；确需改 DUT 时取最小改动并重跑该测试 + 全部适用回归。
- 工具/主机类失败（崩溃、库不匹配）**必须先查文档/AR**，不能直接归为设计问题。

### 自检 TB 的最小写法（可直接套）
```verilog
// 终态唯一标记 + watchdog（示例）
initial begin
  #(`TIMEOUT_CYC);            // 有界兜底
  $display("TEST_FAIL: watchdog timeout at %0t", $time); $finish;
end
// 用例末尾：
if (errors == 0) $display("TEST_PASS"); else $display("TEST_FAIL: %0d errors", errors);
$finish;
```
判据：日志出现 `TEST_PASS` 且无 `TEST_FAIL`；watchdog 触发时打印当前阶段与时间。

## §5 最小复现与版本 bisect（给他人/厂商报问题前）

- **最小复现**：剥到"一个模块 + 一个 TB + 最短激励"仍失败；记录工具版本、命令行、seed、完整日志头。
- **版本 bisect**：在已知正常版本与失败版本之间二分工具/库/源码版本，定位引入回归的版本。
- **跨仿真器仲裁**：XSim 失败而他家通过（或反之）时，先判"设计缺陷 vs 工具缺陷"——用最小复现 + 文档/AR 证据，而不是"换仿真器能过就算过"。
- **无 GUI 取证**：批处理也能导出波形（VCD/WDB 转文本、或用打印级取证），CI 场景不要依赖 GUI。
