# K3 · 踩坑清单：时钟与约束篇（8 条）

> 适用：`[Zynq 通用]` 涉及 PS 时钟/硬核模拟外设；`[Vivado 通用]` 涉及 DRC 与时序收敛。板级数值（bank 电压、球脚号、分压比）以你手头板卡的 XDC/原理图为准——方法是通用的，数值不通用。

## K3-1 bitstream 里的 PS7 时钟配置**不会被应用** → 设计按假设频率跑、整体变慢且零报错 `[Zynq 通用]`

- **现象**：工程里 PS7 配了某 FCLK 频率、XDC 也按它 `create_clock`，但板上 `ol.clock_dict` 显示实际频率不同；按假设频率写死的分频/采样率**整体按比例偏慢**，且**没有任何报错**。
- **触发条件**：任何"PS 时钟驱动 PL 逻辑"的设计，凡按"假设时钟频率"写死分频参数（频率常量、波特率、定时器）。
- **根因（机制要点）**：PYNQ 加载 overlay 时按 `.hwh` 里的 FCLK **分频值**写 SLCR → **改"分频"会生效；只改"目标频率"而分频未随动则不会生效**。bitstream 里烘焙的 PS7 时钟配置不决定板上实际值。
- **排查步骤**：① 上板先读实际时钟 `print(ol.clock_dict)`（值是普通 dict）② 用"设计里已知频率的信号"反推真实频率（如计数器增量对不上 → 逐级折算）③ 让设计适配真实时钟（改频率常量 → Re-Package → 重综合）④ 判据按"期望值 = 假设频率/实际频率"折算后再判定。
- **已验证效果**：实测板上 FCLK 与设计假设差 1.6 倍，改频率常量后计数器增量精确吻合推算；另注意 `clock_dict` 是**加载时快照**，运行时改了 SLCR 它不更新，不能当验收判据。
- **来源**：某次"速率莫名偏慢"的排查。

## K3-2 硬核模拟外设的平均化设置会除低有效数据率 `[Zynq 通用]`

- **现象**：按文档预设值写死数据率画时间轴，时间尺度错 N 倍（N = 平均次数）。
- **触发条件**：XADC 类硬核开了 Channel Averaging，还按"不平均"的转换率当 EOC 率。
- **根因**： averaging 时"除最后一次外不产生 EOC 脉冲"（手册原文）→ 有效 EOC 率 = CONVST ÷ 平均次数。
- **排查步骤**：有效数据率一律按 `EOC 率 = CONVST ÷ 平均次数` 算，接口契约写实测值；用计数器增量实测核对；同时评估平均化对奈奎斯特上限的挤压（上沿可能低于后续滤波链通带，混叠风险真实存在）。
- **已验证效果**：实测速率与"÷平均次数"精确吻合，与假设值差整 N 倍。
- **来源**：某次采集速率标定（手册：UG480）。

## K3-3 DRC `BIVC-1`：同 bank 内 IOSTANDARD 要求的 VCCO 冲突 `[Vivado 通用]`

- **现象**：place 阶段 FAIL，`DRC BIVC-1`（Conflicting Vcc voltages）。
- **触发条件**：同一 bank 里同时放默认 IOSTANDARD 的模拟辅助引脚（如 XADC `Vaux`，不写时默认 LVCMOS18）与 3.3 V 电平的 TMDS/IO。
- **根因**：同 bank 两个 IOSTANDARD 要求不同 VCCO。
- **排查步骤**：给模拟辅助引脚显式写与 bank 实际 VCCO 一致的 IOSTANDARD（实板上该 bank 是 3.3 V 就写 LVCMOS33）；官方 AR 64450 的标准修法即"修正冲突 IOSTANDARD"。
- **已验证效果**：补约束后 place 通过。
- **来源**：某版 HDMI + 模拟采集合并构建。

## K3-4 DRC `PDRC-43`：时钟 IP 内部 PLL/VCO 按"默认输出"推导 → 到 **bitgen** 才爆 `[Vivado 通用]`

- **现象**：综合、实现都过，到 bitgen 阶段才报 `PDRC-43`（PLL/VCO 越界类）。
- **触发条件**：下游原语的 VCO 按"运行时可编程时钟 IP 的**默认输出**"推导（如被推成 100 MHz），而实际输入端周期约束写的是真实频率（如 74.25 MHz）——两者不一致。
- **根因**：DRC 读的是**综合期烘焙进原语的属性**，不是输入端约束。
- **排查步骤**：XDC 显式 `create_clock -name <名> -period <真实周期> [get_nets -hier -filter {NAME =~ *<时钟输出网>*}]`（写运行时真实频率）；**改约束后必须重跑 synthesis**（日志出现良性 `Constraints 18-1056: ... completely overrides ...` 属预期）。同机制参考 AR 50821 / AR 47031。
- **已验证效果**：写真实像素频率后 bitgen 通过，时序报告该时钟域 WNS 3.660。
- **来源**：某版显示链构建。

## K3-5 硬核行为模型不做真实转换/握手，仿真"全绿"不可信 `[Zynq 通用]`

- **现象**：仿真里数据"自动出现"，上板恒 0（参见 K2-13）。
- **触发条件**：用硬核的行为级模型做功能验证。
- **根因**：行为模型直接呈现结果、不走真实握手（如 DRP 读时序）。
- **排查步骤**：凡含硬核交互的路径，TB 必须对硬核**打桩**（按真实握手时序生成激励），或明确标注"此路径仿真不覆盖，以板上实测为准"；金标准比对只对纯数字逻辑有效。
- **已验证效果**：打桩后仿真暴露了"只连数据线不发读选通"的缺陷——此前行为模型完全掩盖。
- **来源**：同 K2-13。

## K3-6 区域时钟缓冲（BUFR）跨 clock region → 整批 hold 违例；pblock 收敛 `[Vivado 通用]`

- **现象**：某类"触发器 → OSERDES"路径上几十条同类 hold 违例，WHS ≈ −1.9 ns，setup 仍全绿；报告结论 not met。
- **触发条件**：区域时钟缓冲（BUFR，`BUFR_DIVIDE` 分频）的负载散布到远端 clock region，布网偏斜达数 ns。
- **根因**：BUFR 是区域缓冲，跨区域扇出偏斜太大。
- **排查步骤（六步，实测收敛路径）**：① 定位时钟源区域：`get_cells -hier -quiet -filter {REF_NAME =~ BUFR*}` 查 LOC → `get_clock_regions -of_objects [get_sites <loc>]`；② 统计负载分布：`get_cells -hier -quiet -filter {NAME =~ *<层级>*}` 逐 cell 读 LOC → region 计数（实测数千 cell 横跨两个 region）；③ 写独立 pblock XDC 放 `constrs_1/new/`：`create_pblock` + `add_cells_to_pblock` + `resize_pblock -add {CLOCKREGION_XnYn:CLOCKREGION_XnYn}`，**只圈受该时钟驱动的 IP**；④ `set_property USED_IN {implementation}`（pblock 只在实现阶段解析，绕开综合期 cell 名不匹配）；⑤ `reset_run impl_1` + `launch_runs impl_1 -to_step write_bitstream`（**无需重综合**，几分钟）；⑥ 读回 timing summary 的 WHS/THS 与结论行复核。
- **失效条件**：① 查子 cell 别用 `get_cells -of_objects`（不返回子 cell），要 `-hier -filter`；② 整层级入 pblock 易拥塞，只圈受影响 IP；③ 新 bit 字节数可能与上一版完全相同，版本以 MD5 为准。
- **已验证效果**：**WHS −1.862 → +0.051 ns、hold 端点 36 → 0、THS −47.43 → 0、结论转 met**，WNS 2.054 → 2.176；重布后上板一次出图成功。
- **来源**：某版显示链 hold 违例收敛（也是 T2 模板"判别实验"段的实战案例）。

## K3-7 引脚约束溯源链：手册表里的 PIN 可能是"数字侧" `[Vivado 通用 / 板级通用]`

- **现象**：按手册表写引脚约束，place/DRC 异常或功能不工作。
- **触发条件**：给模拟输入（或任何多球脚复用信号）写约束；手册表里的 "PIN" 与 XDC 球脚对不上。
- **根因**：同一根外部信号可能有两个球脚——直连 PL 的**数字侧**（功能名**无** `AD` 后缀，不能进模拟硬核）与经分压进硬核的**模拟侧**（功能名**有** `ADxP/ADxN`）；模拟通道号 = 16 + VAUX 索引（如 AD1P → VAUXP[1] → 通道 17/0x11）。
- **排查步骤（四环溯源链）**：① **命名**：从板卡手册确认信号名与"分压前还是分压后"；② **网络名**：对照厂商 XDC 的网络名；③ **球脚**：查 `data/parts/xilinx/<family>/public/ibis/pkg/<型号>_<封装>.pkg`（纯文本），判断某球脚能否进硬核**只看功能名有没有 `ADxP/ADxN`**；④ **内部资源**：由 AD 索引推硬核通道号。无法本地坐实的环，用"上板 1 分钟坐实法"：给已知电压 → 读原始码值反算。
- **失效条件/边界**：专用模拟头（无分压、0–1 V 量程）不可当数字 IO，也别接超过量程的信号；`get_ports` 要先打开设计（`[Common 17-53] No open design`），或直接读 `<bd>_wrapper.v` 的端口列表。
- **已验证效果**：pkg 文件与厂商 XDC 双源一致；板载分压比只能从手册**插图**读出（渲染页面读图计算）——手册关键参数可能只在图里。
- **来源**：某次模拟通道约束（另见经验：厂商教程与芯片手册冲突时以 datasheet 为准）。

## K3-8 仿真超时/计数字面量的 32 bit 溢出 `[Vivado 通用]`

- **现象**：仿真"刚跑就超时"，报错时间 ≈ 预期值的 `mod 2^32`，输出文件一行都没有——看上去像"模块没输出"。
- **触发条件**：`#(A * B * (参数 + C))` 这类"看起来安全"的延时/计数表达式，乘积过 2^31；参数小时不溢出、默认值就挂——"改小就通"更易误判成 DUT 问题。
- **根因**：32 bit 有符号回绕。
- **排查步骤**：看到"超时时间远小于预期"先怀疑溢出，不要怀疑 DUT；改成实数（real 不参与位宽回绕）或显式 `64'd` 扩宽；跑仿真先小规模快速回归（`-g<参数>=<小值>`，秒级）再默认全量，两者都要跑。
- **已验证效果**：实测退出时刻与回绕值精确吻合，改写后两种规模都通过。
- **来源**：某次金标准仿真超时排查。
