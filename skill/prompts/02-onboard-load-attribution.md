# P2 · 提示词工作流：板上负载归因（定基准 → 减法归因 → 单杠杆矩阵 → 四指标判读）

- **类型**：提示词工作流
- **适用场景**：板上同时跑"采集 + 显示 + 网络/插件"，出现波形台阶、事件误报、采样率滑坡、投递率贴底等负载挤占症状；或任何"改了显示/插件/频率之后"的回归验收。
- **使用方法**：先把基准命令与四指标定版（见【前置：定基准】），再整段发送【提示词模板】。
- **失效条件**：① 基准命令含未定版参数时无法横向比较——剧本类参数**必须成对等比改**（实测只提增益不提噪声会"翻面"，现象完全不同）；② 多个杠杆一起改则归因失效；③ 降频类杠杆会改变下游数据密度，判据若依赖固定推送周期需同步复核。
- **已验证效果**：某次联调用"一条减法命令"定位主负载（只关网络监视、保留显示，四指标与全开时几乎无差 → 显示推屏单项吃光余量，网络监视峰值仅 2.7 ms 量级，无辜）；随后单杠杆（快照降频 20→10 Hz）使轮询 29.4→35~36、中途快进 25→0、重标定 3→0；显示渲染单帧 610→127 ms、丢样 11.5→0.6 /s。
- **来源**：某日板测发现"采集被渲染拖慢"：连续 4 层减速带（线程满负荷持锁 / uncached 帧缓冲 / Python 逐列绘制 / 元组广播清屏）用本流程一天内全部拆除。

---

## 前置：定基准（不改代码，只定版命令与指标）

1. **固定一条演示命令**当基准，参数视同代码定版管理，写入核对表：

```
python3 <主脚本> <BIT_PATH> <PKG> <秒数> \
  --source sim --sim-case <剧本> --sim-at <注入时刻> \
  --sim-amp <幅度> --sim-noise <噪声> \        # ← 幅度/噪声必须成对等比改
  --plugins <插件清单> --snapshot-dt <快照周期>
```

2. **固定四指标**（每次实验末尾从收尾 stats 抄）：
   - `poll_hz`（轮询速率——仅代理指标）
   - **中途快进次数**（应=启动一次）
   - `recal_count`（在线重标定次数，应=0）
   - **事件流构成**（事件码多重集 + 卡片簇，对照离线基线表）

## 提示词模板

```text
你是一名实时嵌入式系统性能归因工程师。板上系统由"采集主循环 + 显示推屏 + 网络/插件"组成，
出现 <症状：波形台阶/事件误报/fs 滑坡/投递率贴底>。请协助负载归因，规则如下：

【环境变量】
- 基准命令（定版）：<基准命令全文>
- 四指标基线（离线绿时的值）：poll_hz=<A> / 中途快进=<B> / recal=<C> / 事件流构成=<D>
- 可开关的负载组件：<组件1（如显示推屏）>、<组件2（如网络监视）>、<组件3（插件 X）>…

【规则一：先做减法，一次只关一个组件】
设计最小实验矩阵：
  E0 = 基准全开（引用基线）
  E1 = 关组件1
  E2 = 关组件2（E0 与 E1 的差 = 组件1 的真实占比）
每行实验输出四指标对照表；判定句式："组件X 单项贡献 = E0 − E1；若 E1≈E0 则组件X 无辜"。
禁止在减法阶段改任何参数或代码。

【规则二：定位主负载后，做单杠杆矩阵】
候选杠杆逐项列出（降频 / 改渲染路径 / 提线程优先级 / 降快照频率…），每项标注：
  - 预期收益（基于哪个观测）
  - 副作用（下游数据密度/判据口径是否受影响）
  - 回退方式
一次只动一个杠杆，每项独立可回退；每动一次跑一遍基准命令并抄四指标。
选杠杆原则：先选"结构性减负"（把显示链与插件派发共同挂在的快照回调频率降下来），
再选局部优化（渲染算法）；线程优先级类（chrt/nice）留作最后手段。

【规则三：判读纪律】
- poll_hz 与实际判据（零中途快进 + 满投递 + recal=0）冲突时，以实际判据为准，并注明代理指标作废；
- 结论 = "四指标 + 与离线基线对照 + 判定"，不接受"看起来流畅了"；
- 失败项如实挂账（写明现象与已排除项），不连环修——联调期一次只修一项。

【已知同源坑（先自查再实验）】
- 采集回调里做重活（同步渲染/全量计算/落盘）= 必然丢样；重活应"投递即返回"丢后台线程；
- 渲染节流 wait(max(0, 1/max_fps − 单帧耗时)) 在"单帧耗时 > 间隔"时失效（wait(0)），
  此时降 max_fps 任何取值都无效——先砍单次耗时本身，降频只是减少冻结次数、不减冻结杀伤力；
- 慢 CPU 上向量化选型必须上板微基准，x86 结论会误导（实测 x86 最快的写法在 Cortex-A9 上不是最快）。
```

## 变量表

| 占位符 | 含义 | 示例 |
|---|---|---|
| `<主脚本>` | 板上主程序 | `board_main.py` |
| `<剧本>/<注入时刻>/<幅度>/<噪声>` | 合成源剧本参数 | `pause` / `12` / `10000` / `67`（成对） |
| `<插件清单>` | 本次开的负载组件 | `<组件a>,<组件b>,<组件c>` |
| `<快照周期>` | 快照/推送周期 | `0.1`（10 Hz） |
| `<症状>` | 本次异常表现 | 波形台阶 + 事件误报 |

## 配套判别法（归因过程实测有效）

1. **先花小实验证明"没病的部分"**：寄存器/接口单项读耗时 p50 微秒级（排除读慢）；关显示跑短会话指标正常（排除采集循环本身）；各组件孤立计时全部微秒级（排除单函数慢）→ 剩余嫌疑收敛到**线程交互**。
2. **直调最重函数 ×N 计时**：p50 = 610 ms，而渲染线程实跑 1.57 fps ≈ 1000/610 → 满负荷坐实。
3. **数字矛盾 = 最大线索**：某清屏操作在 cached 与 uncached 两种缓冲上同为 127 ms、"一毫秒都没动" → 推翻"uncached 是主因"的假设，追到语言层（numpy 元组广播写无 SIMD 路径；改 `arr.fill(标量)` 后 2.5 ms，**49 倍**差距）。
4. **帧率节流失效的判别**：改 `max_fps`（5↔25）丢样几乎不变（11.4↔11.7 /s）→ 节流已失效，进入"单帧耗时 > 间隔"分支。

## 预期输出与判读

- 减法矩阵：一张"实验 × 四指标"对照表 + 每组件占比结论；
- 杠杆矩阵：每个杠杆一行"预期/实测/回退"，定版杠杆写入基准命令；
- 终态判定：零中途快进、满投递、`recal=0`、事件流与离线基线一致。

## 来源

某日板测：sim+显示全开时轮询 29.4 贴着投递 28.2，60 s 内中途快进 25 次，波形台阶拉花导致节律混报 + 双重重标。减法矩阵 b5（只关网络监视）与全开几乎无差 → 显示推屏单项吃光余量；单杠杆"快照 20→10 Hz"后四项指标全绿（poll 35~36 / 快进 0 / recal 0 / 与离线基线逐条一致）。显示侧随后用组件孤立计时 + 直调重函数 ×N 的二分法，一天内拆掉四层减速带（详见 K4 篇显示性能条目）。
